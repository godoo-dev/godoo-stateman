<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller args → ir.model.data write | `module`, `name`, `model` are caller-controlled strings passed directly into `ir.model.data` create/write via jsonrpc |
| ir.model.data read → XmlIdRecord | Data returned from Odoo `search_read` is coerced before being trusted; `int(r["res_id"])` guards against Odoo returning False |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | identity.py `write_xmlid` — ir.model.data write | mitigate | Model-mismatch guard: if existing xmlid points to a different model, raise `OdooValidationError` before overwriting — prevents stateman-owned xmlid from silently adopting a record of the wrong model |
| T-03-02 | Tampering | identity.py `find_by_xmlid` — `int(r["res_id"])` coercion | mitigate | Odoo may return `False` for an unset `res_id`; coerce with `int(r["res_id"])` only after confirming records list is non-empty; `find_by_xmlid` returns None for empty results |
| T-03-03 | Information Disclosure | ir.model.data write includes `noupdate: True` | accept | Setting `noupdate=True` signals Odoo not to overwrite this xmlid during module upgrades; this is the correct behavior for stateman-owned records; no security risk |
| T-03-SC | Tampering | uv add / pip install | mitigate | No new packages added in this plan; relies on plan 01 package legitimacy gate |

</threat_model>
