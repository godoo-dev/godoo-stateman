    fetch() implementation (per RESEARCH.md Pattern 1):
    Step 1: `await client.search_read("ir.model.data", [("module","=",xmlid_prefix)],
    fields=["name","model","res_id"], order="name")` → build `managed` dict keyed by row["name"],

    is a pure Python callable, not a coroutine.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI → Odoo jsonrpc | All search_read calls are read-only in this plan; no create/write/unlink |
| DSL Deferred.fn → live data | Deferred.fn is a Python callable from a trusted DSL author; receives resolved IDs from Odoo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Information Disclosure | OdooClient credentials in plan command | mitigate | Credentials read from env vars (GODOO_URL, GODOO_DB, GODOO_USER, GODOO_PASSWORD) — never logged, never hardcoded in defaults. OdooClientConfig isolates credential handling. |
| T-03-03 | Tampering | search_read fields= projection | mitigate | Always use explicit fields= list; never omit fields param (would fetch binary data). field list derived from ResourceNode.fields keys + "id" only. |
| T-03-04 | Denial of Service | ir.model.data scan without limit | accept | Intentional full scan of managed set (no limit) — but fields= projection is minimal (name, model, res_id). For typical config sizes (<1000 resources) this is safe. A2 assumption documented in RESEARCH.md. |
| T-03-05 | Tampering | DataSourceNode selector injection | mitigate | Domain built as `[(k,"=",v) for k,v in sorted(selector.items())]` — values passed as Odoo domain tuple elements, not string-interpolated. OdooClient uses parameterized jsonrpc calls. |
| T-03-01-SC | Tampering | npm/pip/cargo installs | accept | No new package installs; all deps audited in prior phases. |
</threat_model>
