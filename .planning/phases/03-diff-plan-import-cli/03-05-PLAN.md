## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → import command | --model, --id, --module, --name, --force args from operator |
| import command → ir.model.data | import WRITES to ir.model.data — only mutation in Phase 3 |
| Odoo credentials → import command | Same env-var pattern as plan command |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-13 | Tampering | import silent xmlid clobber (SAFE-03) | mitigate | D-11 flow: find_by_xmlid checks existing binding; different res_id → error (with printed message) requiring --force. Verified by test_import_force_guard unit test and SC-5 acceptance test. Never silently overwrites. |
| T-03-14 | Tampering | import with invalid (negative/zero) record_id | mitigate | Validate id_ > 0 before Odoo call; Typer int type rejects non-integers. Step 1 search_read confirms record existence before write. |
| T-03-15 | Spoofing | import writes xmlid to wrong model | mitigate | Step 1 search_read(model, [("id","=",id_)]) confirms the record exists in the declared model. If the record exists in a different model, search returns empty → error before write. |
| T-03-16 | Information Disclosure | Odoo credentials in import command | mitigate | Credentials from GODOO_URL/GODOO_DB/GODOO_USER/GODOO_PASSWORD env vars only. Never in CLI args (would appear in process list). |
| T-03-17 | Elevation of Privilege | --force silently overwriting managed resource | accept | --force is an explicit operator action. Risk is intentional by design (operator acknowledged the collision). The non-force path always errors (with message) — this is the default-safe posture. |
| T-03-01-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan. |
</threat_model>
